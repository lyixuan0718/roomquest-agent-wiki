# Context 與 Grounding

## 核心概念

模型不應憑自己的記憶猜測場景，而要使用目前任務提供的可靠上下文。RAG 的基本思路是先取得相關資料，再把資料交給模型；但檢索結果相似，不代表內容必然正確或足以回答。

## RoomQuest 應用

RoomQuest 只把主持人確認過的場景資料交給 Planner。未出現在場景 JSON 的物品，不能出現在關卡中。照片解析失敗時，主持人可以改用手動輸入，後續流程仍可運作。

## 限制

場景 JSON 是封閉世界：照片外或漏拍的物品不在資料裡。因此程式能保證的是「在已確認資料中唯一」，不能宣稱整個現場百分之百唯一。

## 檢查問題

- 這個敘述能否對回場景資料？
- 資料來源是否明確？
- 是否把相似度誤當成正確率？
